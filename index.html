Code-driven agent runs on UHP

A Paperclip ServerAdapterModule that runs agents on HarnessRouter over the Unified Harness Protocol (UHP). One Paperclip run, one UHP task — conversation continuity, cancellation, usage and error classification, mapped cleanly onto Paperclip's execution contract.

How a run flows

From Paperclip to HarnessRouter and back — every step guaranteed.

1

Paperclip run

Your app submits a run through the adapter contract.

▸
2

UHP task

One run becomes one UHP task on HarnessRouter.

▸
3

Harness executes

Claude Code, Codex, Hermes, Aider, or OpenHands runs it.

▸
4

Stream returns

Usage, cancellation, and errors flow back to Paperclip.

What the mapping guarantees

Semantic guarantees the adapter makes at every step of a run.

✓

Failed request ≠ failed task

A non-2xx response carries a UHP error envelope and is classified. A task that already ran is never retried — and never billed twice.

🔁

Dropped stream recovery

If the SSE connection ends early, the adapter reads the stored response back by id. The stream is an optimisation; the stored response is the truth.

🔗

Conversation continuity

Sessions are response ids. previous_response_id continues the conversation; a mismatched id starts fresh instead of failing.

🔑

Secrets stay out of logs

API keys live in the environment or a chmod 600 file. Tool-call arguments are never rendered — only the tool name.

⏱

Smart retries

Retries only happen before the first task event arrives, under a deterministic idempotency key per run.

🧪

testEnvironment()

Three read-only probes at startup: UHP discovery, authenticated harness listing, and harness existence.

Usage example

Register the adapter alongside Paperclip's built-in adapters.

index.ts
// Register the adapter with Paperclip import adapter from "@switchboard/harness-adapter"; // Its `type` is "harnessrouter" adapter.execute( ctx, { baseUrl: "http://127.0.0.1:3200/api/harness", apiKeyFile: "~/.harnessrouter/api-key", harnessId: "codex", timeoutSeconds: 900, } );
